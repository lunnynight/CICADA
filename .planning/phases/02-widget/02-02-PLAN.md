**Challenge:** SetupPage calls InstallerService static methods directly in initState -> _detect(). Per D-07, we do NOT use mockito to mock static methods. Instead, we need a strategy to handle these calls in tests.

**Strategy — catch and handle ProcessException gracefully:**
SetupPage's _detect() method has `if (!mounted) return;` guards and catches exceptions. In the test environment, InstallerService static methods will throw because there's no real `node`/`openclaw` CLI. The widget handles this via try/catch or the methods return defaults.

First, read InstallerService to verify what happens when CLI tools are missing:
- `isNodeVersionSufficient()` calls `Process.run('node', ...)` — will throw ProcessException in test
- `checkOpenClaw()` calls `Process.run('openclaw', ...)` — will throw ProcessException in test
- `isBundledAvailable()` checks file existence — returns false in test
- `getBundledVersions()` reads asset file — returns null in test

**Approach:** Since SetupPage catches errors in _detect() and sets state accordingly (nodeInstalled=false, openclawInstalled=false, detecting=false), the widget should render in "nothing installed" state after _detect() completes/fails. Use `await tester.pumpAndSettle()` with a timeout to let async operations complete.

If `pumpAndSettle` times out (due to animations or unresolved futures), use `await tester.pump(const Duration(seconds: 1))` instead.

**Challenge:** HomePage has two issues for testing:
1. `_checkStatus()` calls `InstallerService.isGatewayRunning()` — static method, will throw ProcessException in test
2. `Timer.periodic(5s)` — must be handled to avoid test leaks
3. Imports 16 page widgets, some of which have their own heavy dependencies

**Strategy:**
HomePage's `_checkStatus()` has `if (mounted && running != _serviceRunning)` guard. If `isGatewayRunning()` throws, the catch in the method (or lack thereof) may cause issues. Read the method carefully:

```dart
Future<void> _checkStatus() async {
  final running = await InstallerService.isGatewayRunning();
  if (mounted && running != _serviceRunning) {
    setState(() => _serviceRunning = running);
  }
}
```

If `isGatewayRunning()` throws, the exception propagates uncaught. We need to handle this.

**Approach:** Use `tester.runAsync()` for tests that need real async, and use `fakeAsync` with manual time control where possible. For the static method issue:

Option A (preferred): Check if InstallerService.isGatewayRunning has a try/catch internally. If it does, it returns false on error and tests work.
Option B: If it throws, we may need to add a minimal `@visibleForTesting` static override point. Keep this as small as possible.

**Test setup:** Set screen size to wide (>800px) for sidebar tests:
